# Personal Blog

A personal blog hand-built on the **Payload Website Template** (Next.js App Router + Payload CMS), instead of a SaaS CMS or off-the-shelf theme. The entire UI, plugins, and features are custom-written in this repo.

For technical direction, tech stack, and code conventions: see [CLAUDE.md](./CLAUDE.md).

---

## Tech stack

- **Next.js** (App Router) — the public site and `/admin` run in one app.
- **Payload CMS 3.x** — configured in `src/payload.config.ts`, admin panel auto-generated from config.
- **Database** — **Postgres** (adapter `@payloadcms/db-postgres`), used from the start instead of the CLI's Mongo default.
- **Tailwind CSS v4** for styling.
- **Lexical richtext** (`@payloadcms/richtext-lexical`) for post content.
- **Hosting**: self-managed VPS (not Vercel/Netlify).

## Main directory structure

```
src/
├── app/            # Next.js routes — (frontend) and (payload)
├── collections/    # CMS definitions: Posts, Pages, Categories, Media, Users
├── Header/         # Global config + header component
├── Footer/         # Global config + footer component
├── blocks/         # Layout builder blocks
├── heros/          # Hero section variants
├── fields/         # Fields shared across collections
├── access/         # Access control
├── endpoints/      # Custom REST endpoints
├── hooks/          # Payload hooks
├── plugins/        # Payload plugin config
├── providers/      # React context providers
├── search/         # plugin-search config
├── components/     # Shared React components
└── utilities/      # Utility functions
```

## Repository Scope

### ✅ In the repo
- Next.js + Payload source code (collections, blocks, fields, components...)
- Build, lint, TypeScript config
- `payload-types.ts` (generated by `pnpm generate:types`, committed so CI/build doesn't need to regenerate)
- Documentation (`docs/`)
- `.env.example`

### ❌ Not in the repo
- `node_modules`, build output (`.next/`, `/build`)
- The real `.env` file (secrets, connection string)
- User-uploaded media (`public/media`)
- Database dumps

See [.gitignore](./.gitignore) for details.

## Post content

Posts are authored through **Payload's admin UI** (`/admin`) and stored in the database — no Markdown files + Git for writing. Rich text uses Lexical and can render out as layout blocks.

## Multi-language

Uses Payload's built-in localization, `vi` as the default locale + `en`, declared in `payload.config.ts`.

## Reader comments

Uses [Giscus](https://giscus.app) embedded into the post-detail component — no separate comment backend needed.
